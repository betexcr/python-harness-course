[![Python](https://img.shields.io/badge/python-3.13+-blue?logo=python)](https://www.python.org/)

An incremental, educational project that walks through building an **AI agent harness** from the ground up — starting with a basic chatbot and evolving into a full-featured agent framework with tool calling, MCP (Model Context Protocol) integration, persistent memory, and a multi-model backend registry.

Each Python file in the repo represents one stage of the journey. Read them in order to see how the complexity grows:

| File | Stage | What it adds |
|------|-------|-------------|
| `chat.py` | v0 — Chat | Basic chat with a local Ollama model, interactive model selection, response timing, cross-platform notification |
| `tool_calling.py` | v1 — Tools (single-turn) | Tool calling with file tools (`list_files`, `read_file`, `write_file`). Runs a tool **once** per turn. |
| `tool_calling_loop.py` | v2 — Agent Loop | The real trick: loops through tool calls until the model produces a final answer. Adds `create_file`, `combine_files`, and a detailed system prompt. |
| `saving_memory.py` | v4 — Memory | Persistent memory stored in a Markdown file. Conversation history survives across turns. |
| `harness.py` | v4 — Full Harness | The complete system: all three pillars together, async agent loop, slash commands, multi-model registry. |

## Features

- **Multi-model support** — Query local Ollama models, OpenAI GPT, or Anthropic Claude through a single OpenAI-compatible client. Switch at runtime with `/model`.
- **Agent loop** — Automatically chains tool calls: the model decides which tools to call, the harness executes them, and the results are fed back until the model is done.
- **File tools** — Built-in tools to list, read, create, write, and combine files in the workspace.
- **MCP integration** — Connect to any [Model Context Protocol](https://modelcontextprotocol.io/) server via `mcp_servers.json`. Remote tools are merged into the available toolset automatically.
- **Persistent memory** — Facts about the user are saved to `memory.md` and injected into the system prompt on every start.
- **Slash commands** — `/models`, `/model <name>`, `/tools`, `/memory`, `/quit`.

---

## How It Works

The core of every agent harness is this loop (visible in `tool_calling_loop.py` and refined in `harness.py`):

1. Send the conversation history — including tool schemas — to the model.
2. If the model responds with **tool calls**, execute each tool and append the result as a `tool` message, then loop back to step 1.
3. If the model responds with **no tool calls**, that's the final answer — return it.

This simple loop is what transforms a chatbot into an *agent* that can actually *do* things: read files, fetch web pages, save memories, and so on.

## Installation

1. **Clone the repository:**

   ```bash
   git clone https://github.com/<your-username>/python-harness-course.git
   cd python-harness-course
   ```

2. **Install dependencies with uv:**

   ```bash
   uv sync
   ```

   This creates a `.venv/` virtual environment and installs all pinned dependencies from `uv.lock`.

3. **Set up your environment:**

   ```bash
   cp .env.example .env
   ```

4. **Edit `.env`** and fill in the values you need (see [Configuration](#configuration)).

5. **(Optional) Start Ollama** if you plan to use local models:

   ```bash
   ollama serve              # in one terminal
   ollama pull qwen2.5:3b    # in another
   ```

## Architecture

The full harness (`harness.py`) has three pillars:

### 1. MCP (Model Context Protocol)

Connects to external tools via the [Model Context Protocol](https://modelcontextprotocol.io/). Servers are defined in `mcp_servers.json` and launched as subprocesses (the same format used by Claude Desktop). Their tools are discovered at startup and merged into the unified toolset.

```python
# Each server is launched via stdio and its tools become first-class citizens
async def connect_mcp(stack: AsyncExitStack):
    config = json.loads(MCP_CONFIG.read_text())
    for name, spec in config["mcpServers"].items():
        params = StdioServerParameters(command=spec["command"], args=spec["args"])
        read, write = await stack.enter_async_context(stdio_client(params))
        session = await stack.enter_async_context(ClientSession(read, write))
        await session.initialize()
        # ... tools are appended to TOOL_SCHEMAS
```

### 2. Memory

A simple but powerful approach: `memory.md` is a plain Markdown file read into the system prompt at startup. The `save_memory(fact)` tool lets the agent append facts about the user that persist across sessions.

```
# memory.md
- User prefers Qwen models for local development.
- Working on a Python agent harness course project.
```

### 3. Model Registry

A `ModelConfig` pydantic model + a `MODELS` dictionary map any OpenAI-compatible endpoint to a named backend. Local Ollama, OpenAI GPT, and Anthropic Claude all share the same `AsyncOpenAI` client — just different `base_url` and `api_key`.

```python
MODELS: dict[str, ModelConfig] = {
    "local":      ModelConfig(base_url="http://localhost:11434/v1", model=os.getenv("MODEL")),
    "gpt":        ModelConfig(base_url="https://api.openai.com/v1",  model="gpt-5-nano"),
    "claude":     ModelConfig(base_url="https://api.anthropic.com/v1/", model="claude-haiku-5-5"),
}
```

### The Agent Loop

The heart of the harness (adapted from `tool_calling_loop.py`):

```
while True:
    response   = model(messages, tools=schemas)
    message    = response.message
    if no tool_calls:   ← model answered, we're done
        return message.content
    append message
    for each tool_call:
        result = execute(tool_name, tool_args)
        append {role: tool, content: result}
    ← loop back, feed results to the model
```

## Adding MCP Servers

Edit `mcp_servers.json` to add any MCP-compatible server. Each entry follows the same schema:

```json
{
  "mcpServers": {
    "time": {
      "command": "uvx",
      "args": ["mcp-server-time"]
    },
    "fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"]
    },
    "my-server": {
      "command": "python",
      "args": ["-m", "my_mcp_server"]
    }
  }
}
```

On startup, the harness will attempt to connect to each server. Servers that fail to start are logged and skipped (so you can keep entries that aren't always available).

## Workspace & Memory

### Workspace (`workspace/`)

A folder for user files. The built-in tools (`list_files`, `read_file`, `write_file`, `create_file`, `combine_files`) operate exclusively within this directory. It is git-ignored via `.gitignore` so your personal files stay local.

### Memory (`memory.md`)

A plain-text Markdown file that stores facts the agent should remember across sessions. It is read into the system prompt at startup, and the `save_memory` tool appends new facts as bullet points. Delete or edit the file manually at any time.
